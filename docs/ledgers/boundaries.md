# The boundary ledger

This is the third of the [four ledgers](../../CONTRIBUTING.md#the-four-ledgers)
that judge smock's tests. Every limit that a spec or smock's documents state
is tested at the limit and just past it, with the smallest input that
crosses it. A limit in the code that no document states is a finding: once
the maintainer confirms it, the documents state it, and it is tested like
the others. Each row below is one limit, or one range with its two ends. It
cites where the limit comes from, names the packages that hold it, and
names the tests on each side of it, or the ticket that adds what is
missing. The [use-case ledger](use-cases.md) does the same for features and
messages.

[Keeping the ledgers current](../../CONTRIBUTING.md#keeping-the-ledgers-current)
in CONTRIBUTING says how each change keeps them up to date.
`scripts/check-ledgers.py` checks every row on every push, as it checks
the use-case ledger.

For a range, "at the limit" names the tests that accept its ends, and
"just past it" those that refuse the value past each end. Where a test
holds both sides, it is named in both columns. A test that a row names is
the only test of that row for the
[removal rule](../../CONTRIBUTING.md#removing-a-test).

## Baseline

A survey of the documents at d953f320 tabled the 40 most important limits.
Each was checked again on the tip of the test review's integration branch,
be2b8e0b, against the code and the tests there. Where a survey row held
several limits, they are split here into rows with the same number and a
letter (L15a, L15b, ...). Rows L41 to L43 are limits that the test review's
spec names beside the survey's 40.

| | At d953f320 | At be2b8e0b |
|---|---|---|
| The survey's 40 rows | about 33 tested on both sides, as the survey counted; 32, rechecked | 34 tested on both sides, 6 partly |
| The 68 rows of this ledger | | 56 tested, 11 partly, 1 open |

A survey row counts as tested on both sides only when every row split from
it is. The recheck at d953f320 differs from the survey's own marks in which
rows it counts: see below.

This ledger is not yet every limit the documents state. The import guide's
[Limits](../importing-openapi.md#limits) alone list ten, and the gRPC
guides and the template helpers more. Gap G3 is the rest.

## Changes since the survey

Rows whose status changed between d953f320 and be2b8e0b, and why:

- **L37a to L37d**, the settings' maxima: ports at 65535, `--replicas`,
  `--header-count-limit` and `--journal-max-entries`. #285 tested each at
  its maximum and just past it, in-process. The three ranges that no
  document stated were confirmed by the maintainer on 2026-11-17, and the
  running guide states them.
- **L38**, the ClientHello reader's cap: no test at d953f320. #289 tests
  it at 65,535 and 65,536 octets received. The maintainer confirmed the
  cap as the code has it, and the running guide states it.
- **L39**, the self-signed certificate's validity: no test at d953f320.
  #290 tests it. The hour before generation was in no document; the
  maintainer confirmed it, and the running guide states it.
- **L40c**, `smock import-openapi`'s 100 temporary names: no test at
  d953f320. #291 tests the names at the limit and past it. The maintainer
  confirmed the names, and the import guide states them.
- **L41**, the 16 MiB of full names: a test existed at d953f320, but its
  set at the bound was refused for another reason. #284 tests the bound
  exactly, and the gRPC guide now says how the names are counted, as the
  maintainer confirmed.
- **L42**, the reason phrases: four were never checked. #284 checks every
  status smock names.

Rows that the survey had wrong at d953f320, and that are unchanged since:

- **L04 and L05**: the survey had HTTP/2's header lists tested only past
  their limits. The tests also send a list at the limit, and a block at
  twice it.
- **L07**: the survey had the 16,384-octet frame size tested only past it.
  A test also sends DATA frames of exactly 16,384 octets, which are taken.
- **L15b**: the survey had `after` tested on both sides. Its value past
  each end is refused, but no test takes 2^53 - 1.
- **L17**: the survey had `dataWrites` tested below its range. A Stub with
  101 writes is refused, but none with 100 is shown to load (#334).
- **L23a and L23b**: the survey had `fake.hex` and `fake.words` tested on
  both sides. Their upper ends are tested, but not their lower ends, and
  `fake.words(101)` is not refused by any test.
- **L35c and L35e**: the survey had RE2's program size and the DFA's
  budget tested on both sides. Neither is tested at its limit, and the
  program size only well past it.
- **L36**: the survey had XML's depth tested only past it. The test also
  parses elements nested exactly 256 deep.
- **L37e to L37h**: the survey had the ranges of the other numeric
  settings tested on both sides. Their ends are refused just past them,
  some of them, but no document states these ranges: they are findings,
  which #320 takes to the maintainer.

## Gaps that no ticket closes

A gap that no ticket of the test review closes is filed as an issue. Until
it has its number, its row names #286, the ticket that files it.

- **G3.** This ledger lists the survey's 40 limits and three more. The
  documents state other limits that no row lists yet, such as the ten of
  the import guide's [Limits](../importing-openapi.md#limits). Step 3's
  tickets test the limits this ledger lists in their package, so a limit
  missing here is tested by no ticket. The gap is to list every limit the
  documents state, each with its tests or a ticket.
- **G4.** No test takes an `after` of 2^53 - 1, the largest the Admin
  API's guide allows, in the unmatched list's query string, which `server`
  reads (L15b). #333 tests the Journal query's body, which `engine`
  reads, as a limit of this ledger in `engine`.
